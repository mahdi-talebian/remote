# طراحی: حالت شبکه محلی (LAN) — حذف کامل Tailscale

- **تاریخ:** 2026-09-12
- **وضعیت:** تأییدشده در گفتگو (همه بخش‌ها با تأیید کاربر)
- **مسیر اسکیل:** brainstorming (Architectural) → writing-plans → پیاده‌سازی با TDD

## ۱. خلاصه و هدف

برنامه از «اتصال از راه دور از طریق Tailscale» به «اتصال **فقط داخل شبکه محلی**» تغییر می‌کند. سناریوی هدف: کامپیوتر مدیر و کامپیوترهای کارمندان همگی **زیر یک مودم/روتر** هستند.

جریان نهایی:

```
سمت کارمند (یک‌بار، با Admin):
  SetupWizard → نصب sshd + اکانت it_remote + فایروال LAN
              → نمایش/کپی آدرس: ssh it_remote@192.168.x.y

سمت مدیر (همیشه):
  AdminConsole → «بروزرسانی» = اسکن زیرشبکه (پورت 22)
              → لیست سیستم‌ها (آنلاین/آفلاین) → دوبار کلیک = ترمینال SSH
```

**محدودیت پذیرفته‌شده (تصمیم کاربر):** بدون Tailscale، بیرون از شبکه‌ی محلی هیچ راه اتصالی وجود ندارد. پورت‌فوروارد کردن مودم صریحاً خارج از محدوده است (ریسک امنیتی).

## ۲. تصمیمات تأییدشده

| تصمیم | انتخاب |
|---|---|
| سرنوشت Tailscale | **حذف کامل** (نه حالت اختیاری) |
| کشف سیستم‌ها | **اسکن خودکار زیرشبکه** (نه دستی) |
| رویکرد آدرس‌دهی | **IP محور** (رویکرد ۱)؛ reverse-DNS فقط برای نمایش نام |
| رزرو IP در مودم | فقط به‌عنوان **نکته اختیاری در README** (مکانیزم اصلی نیست) |
| فیچرهای بعدی (اجرای دستور و...) | معلق؛ بعد از این تغییر معماری، طراحی‌شان از سر گرفته می‌شود |

## ۳. معماری کلی

- لایه اتصال: **sshd روی IP محلی** — همه‌چیز روی SSH موجود سوار می‌ماند.
- کشف: **TCP connect sweep** روی پورت ۲۲ کل `/24` محلی، موازی و async.
- تشخیص سیستم‌های «ما»: هر میزبان شبکه که پورت ۲۲ باز داشته باشد در لیست می‌آید؛ نام میزبان (reverse-DNS) کمک می‌کند بقیه (روتر/NAS) از سیستم‌های کارمند تشخیص داده شوند.
- حافظه‌ی سیستم‌های دیده‌شده (known-hosts): سیستم‌هایی که در اسکن‌های قبلی دیده شده‌اند ولی الان جواب نداده‌اند با برچسب «آفلاین» نمایش داده می‌شوند.
- حذف کامل: پارامتر کلید Tailscale، نصب/اتصال Tailscale، منطق `ts.net`/tailnet/آدرس ایملی، `tailscale-guide.md`، mock توی Tailscale، بخش‌های Tailscale در README، دکمه «ویزارد استقرار» از منوی کنسول **حذف نمی‌شود** (برای تست محلی مفید است).

## ۴. تغییرات فایل‌به‌فایل

### ۴.۱ `deploy-employee.ps1` (v4 — LAN mode)

- **پارامترها:** حذف `-TailscaleAuthKey` و `-SkipTailscale`. باقی: `-AdminPassword` (اجباری)، `-Hostname`، `-UserName`، `-AllowNonAdmin`. **جدید:** `-LanIp` (اختیاری؛ تحمیل IP برای تست/حالت‌های خاص).
- مراحل از ۵ به ۴: (۱) sshd — بدون تغییر؛ (۲) اکانت `it_remote` — بدون تغییر؛ (۳) فایروال LAN؛ (۴) ساخت آدرس.
- **فایروال (ویندوز):**
  - حذف قانون قدیمی `OpenSSH Server (Tailscale only)` (مسیر ارتقا از نسخه قبل).
  - ساخت `OpenSSH Server (LAN)`: Inbound/TCP/22/Allow با `-Profile Private,Domain`.
  - اگر پروفایل شبکه‌ی متصل «Public» باشد → خودکار به «Private» تغییر می‌کند (`Set-NetConnectionProfile`) با ثبت در لاگ. (بدون این، قانون فایروال اعمال نمی‌شود.)
- **تشخیص IP محلی:**
  - ویندوز: اینترفیسِ دارای **مسیر پیش‌فرض** (`Get-NetRoute -DestinationPrefix 0.0.0.0/0`) → اولین IPv4 آن اینترفیس؛ حذف loopback و APIPA (`169.254.*`). fallback: اولین IPv4 مناسب.
  - لینوکس: `ip route get 1.1.1.1` (یا `hostname -I`) → IP منبع.
  - override با `-LanIp`.
- **آدرس:** همیشه `ssh <user>@<IP>`؛ نام دستگاه فقط به‌عنوان «آدرس جایگزین» چاپ می‌شود (ممکن است resolve نشود). منطق tailnet/`@`/DNSName حذف.
- **فایل‌ها:** `ssh-address.txt` (خطوط: SSH-ADDRESS، Hostname جایگزین، User، Log)، `last-address.txt` (یک خط: `ssh user@ip`)، `deploy.log`. **نام و فرمت مارکرها (`SSH-ADDRESS:`، `IP-FALLBACK:`، `[DEPLOY-STATUS]`) عوض نمی‌شود** — ویزارد به آن‌ها وابسته است. `IP-FALLBACK` از این پس همان IP محلی است (برای سازگاری مارکر حفظ می‌شود).
- خط اول لاگ: `= Remote Admin deploy v4 (LAN mode) =`.
- کد خروج ۰ = موفق (مسیر شکست tailscale حذف می‌شود).

### ۴.۲ `gui/SetupWizard.ps1`

- حذف: فیلد «کلید Tailscale» + اعتبارسنجی `tskey-auth-` + env var `RA_KEY`.
- فرم: نام دستگاه + رمز + تکرار رمز + «نمایش رمز». ارتفاع GroupBox تنظیم می‌شود.
- بقیه بدون تغییر: ارتقای خودکار به Admin، لاگ زنده، بازیابی ۴ لایه‌ی آدرس (استریم → خروجی کامل → فایل‌ها → حدس از hostname)، `Parse-Address` با همان قواعد.

### ۴.۳ `gui/AdminConsole.ps1`

- حذف: کشف `tailscale.exe`، منطق tailnet، شاخه‌های tailnet در `Build-Address`.
- `Build-Address` → همیشه `"$user@$IP"` (تابع حفظ می‌شود چون تست‌ها آن را استخراج می‌کنند).
- **رفرش:** همان الگوی `Start-Job` + تایمر فعلی؛ داخل job: تشخیص زیرشبکه (`Get-LocalSubnet`) + اسکن (`Find-SshHosts`) → خروجی: Rows + Subnet + Error.
- **حافظه known-hosts:** فایل JSON در `%LOCALAPPDATA%\RemoteAdminConsole\known-hosts.json` (در لینوکس: `~/.remote-admin-console/`)؛ رکورد: `{ip, host, lastSeen}`. بعد از هر اسکن: یافتیده‌ها=آنلاین و `lastSeen` تازه؛ دیده‌شده‌های قبلیِ غایب=آفلاین. چک‌باکس «نمایش آفلاین‌ها» **حفظ می‌شود** و ردیف‌های آفلاینِ حافظه را فیلتر می‌کند. (اصلاحیه‌ی بخش ۱ گفتگو: چک‌باکس حذف نمی‌شود، چون حافظه‌ی آفلاین معنا پیدا می‌کند.)
- ستون‌ها: وضعیت / نام دستگاه / آدرس SSH / **IP شبکه محلی** (تغییر عنوان از «IP شبکه خصوصی»).
- نوار وضعیت: `X آنلاین • Y آفلاین (کل: Z) | زیرشبکه: 192.168.1.0/24`.
- اتصال/کپی/ذخیره/جستجو/ویزارد: بدون تغییر منطقی.

### ۴.۴ `get-addresses.ps1` → `scan-network.ps1` (تغییر نام)

- همان فلسفه‌ی اسکریپت مستقل؛ اسکن زنده را در CLI انجام می‌دهد و `ssh-addresses.txt` می‌سازد.
- پارامترها: `-UserName`، `-Subnet` (اختیاری، مثال `192.168.1.0/24`)، `-ShowOffline` (حذف — CLI فقط نتیجه‌ی زنده را نشان می‌دهد).
- توابع `Get-LocalSubnet` و `Find-SshHosts` **در همین فایل و (کپی مستقل) در AdminConsole** قرار می‌گیرند — مطابق الگوی فعلیِ «اسکریپت مستقل، بدون ماژول مشترک» در این ریپو؛ تست‌ها از هر دو فایل واقعی استخراجشان می‌کنند.

### ۴.۵ `deploy-via-domain.ps1`

- مکانیزم WinRM/PsExec/GPO بدون تغییر؛ فقط `-TailscaleAuthKey` حذف و `ArgumentList` با امضای جدید deploy هماهنگ می‌شود.

## ۵. جزئیات فنی اسکنر

```
Get-LocalSubnet            → '192.168.1.0/24' (اینترفیسِ مسیر پیش‌فرض؛ فقط IPv4؛ حذف loopback/APIPA)
Find-SshHosts -Subnet x    → لیست {IP, Host} که پورت 22 جواب داد
```

- الگوریتم: شمارش میزبان‌های `/24` (حذف `.0`/`.255` و IP خودمان) → برای همه `TcpClient.BeginConnect` صدا زده می‌شود → انتظار جمعی با بودجه‌ی کلی (~۵ ثانیه) → بستن سوکت‌ها. (async و هم‌زمان؛ سریع و سازگار با PS 5.1)
- نام میزبان: تلاش `GetHostEntry` (reverse-DNS) با timeout کوتاه؛ شکست = رشته خالی.
- شبکه‌ی بزرگ‌تر از `/24`: به‌صورت پیش‌فرض فقط `/24` حاوی IP خودمان اسکن می‌شود + پیام؛ override کامل با پارامتر `-Subnet` (در CLI) ممکن است.
- «آنلاین» = پورت ۲۲ در همین اسکن جواب داد.

## ۶. عیب‌یابی/لبه‌ها (مستند در README)

| مشکل | توضیح |
|---|---|
| هیچ سیستمی پیدا نمی‌شود | AP isolation مودم (جداسازی کلاینت‌ها) — خاموشش کن؛ یا پروفایل Public |
| وصل می‌شد، حالا نه | IP عوض شده → «بروزرسانی» بزن (اسکن پیداش می‌کند) |
| ویزارد موفق ولی در لیست نیست | پروفایل شبکه Public است → ویزارد خودش Private می‌کند؛ بعد دوباره |
| پورت ۲۲ روی روتر/NAS هم باز است | طبیعی است — ستون «نام دستگاه» کمک می‌کند؛ فقط سیستم‌های خودت را انتخاب کن |

## ۷. تست‌ها (E2E — `tests/run-e2e.ps1`)

- **حذف:** `tests/mock/tailscale` و همه‌ی تست‌های وابسته به آن.
- **پیش‌نیاز سندباکس:** نصب `pwsh`، `sshd` (پورت ۲۲)، `sshpass` — دیگر mock لازم نیست.
- تست‌های جدید/تغییریافته:
  1. parse همه‌ی اسکریپت‌ها (شامل `scan-network.ps1` جدید).
  2. استقرار بدون هیچ کلید → exit 0 + `[DEPLOY-STATUS] SUCCESS` + آدرس = `it_remote@<IP واقعی شبکه سندباکس>` (تشخیص خودکار؛ نه 127.0.0.1).
  3. override با `-LanIp 127.0.0.1` → آدرس loopback (تست پارامتر).
  4. **ورود واقعی SSH با رمز به IP واقعی شبکه** (سخت‌گیرانه‌تر از نسخه قبل که فقط 127.0.0.1 بود).
  5. رمز غلط → شکست واضح (منفی).
  6. `Get-LocalSubnet`/`Find-SshHosts` (استخراج AST از هر دو فایل واقعی): math زیرشبکه (`192.168.1.15/24` → میزبان‌های ۱..۲۵۴) + اسکن واقعی `127.0.0.0/24` → پیدا کردن 127.0.0.1 (sshd واقعی).
  7. `Parse-Address` ویزارد با فرمت‌های IP (`SSH-ADDRESS: ssh it_remote@192.168.1.50`، bare، خط last-address.txt) + رد مارکر ناقص.
  8. `Build-Address` کنسول → `user@IP`.
  9. بازتولید `tests/REPORT.md`.
- روش: TDD — اول تست قرمز، بعد پیاده‌سازی سبز.
